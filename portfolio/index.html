01

소개

통신 현장에서 배운 협업과 개발 과정에서 익힌 검증 습관을 연결했습니다. 어떤 일을 맡았고 어떻게 성장해 왔는지 소개합니다.

이전에는 통신 회선과 장비 연결을 설계하고, 현장 공사 일정과 고객 요청을 조율했습니다. 서로 다른 입장을 정리하고 업무가 이어지도록 설명하는 경험을 쌓았지만, 이를 개발 직무의 강점으로 보여 주는 일은 쉽지 않았습니다.

백엔드를 공부하며 Clean4U에서 로그인·이메일 인증과 직원 관리 기능을 개발했습니다. 이후 보안 교육에서는 익숙하지 않은 실습을 그냥 넘기지 않고, 자료를 찾아 재학습하거나 Notion에 정리해 다음 실습에 활용했습니다.

최근 Protective DNS 팀 프로젝트에서는 URL 위험도 판단 기준과 정책 엔진을 맡고, 팀원들과 적용 범위와 발표 자료를 검토했습니다. 저는 기능을 완성하는 데 그치지 않고 판단 근거와 검증 결과를 설명할 수 있는 개발자를 지향합니다.

03

대표 프로젝트

어떤 문제를 해결하려 했고, 팀에서 어떤 역할을 맡았는지 중심으로 소개합니다. 상세 기능과 기술 자료는 각 프로젝트 페이지에서 확인할 수 있습니다.

01 · 팀 캡스톤 · 보안

Protective DNS

가짜 피해구제·기관 사칭 사이트의 위험을 알리는 서비스

공식기관을 사칭한 사이트로 잘못 접속하는 위험을 줄이기 위해, URL을 분석해 차단·경고·허용·판단 보류로 구분하는 팀 웹서비스를 만들었습니다.

4인 팀에서 Python 기반 위험도 판단 규칙과 정책 엔진을 담당했고, 판단 근거를 보여주며 DNS 적용 단계와 구분하도록 구성했습니다.

Clean4U

세탁소의 운영 업무를 한곳에서 관리하는 서비스

고객·주문·직원·근무 일정이 흩어져 관리되는 불편을 줄이기 위해 세탁소 통합 관리 웹서비스를 팀으로 개발했습니다.
