# 나의 별 프로젝트 계획서 · 로그 한눈에

## 1. 프로젝트 개요
- **프로젝트명:** 로그 한눈에 — 보안 이상징후 분석기
- **한 줄 소개:** 보안 로그를 분석해 이상징후를 탐지하고, 발생 원인과 위험도를 쉽게 확인할 수 있는 웹앱
- **대상 사용자:** 보안관제 업무를 배우는 입문자 및 로그 분석을 연습하려는 교육생
- **문제:** 로그 원문만 보면 어떤 활동이 위험한지 초보자가 파악하기 어렵다.
- **해결:** 예시 로그 또는 사용자 CSV를 넣으면 탐지 결과를 사건별로 묶고 발생 근거를 설명한다.
- **완료 목표:** 로그인 없이 공개 URL에서 예시 로그 조회·CSV 분석·위험도 확인·결과 다운로드가 정상 작동한다.

## 2. 핵심 기능 3가지
1. **로그 불러오기:** 개인정보가 없는 예시 로그를 기본 제공하고, 사용자가 CSV를 업로드해 결과를 확인한다.
2. **이상징후 탐지:** 5분 내 반복 로그인 실패, 심야 성공 로그인, 트래픽 급증을 탐지하고 탐지 이유를 표시한다.
3. **결과 시각화·내보내기:** 탐지 목록, 사건별 위험도, 발생 시각·근거를 보여주고 분석 리포트를 CSV로 다운로드한다.

## 3. 구현 범위와 우선순위
### 필수(MVP)
- 웹 첫 화면에 대상 사용자·사용 목적·3단계 사용법 표시
- 샘플 CSV 1개 이상 제공 및 CSV 업로드
- 탐지 3개 규칙과 근거 코드/설명 표시
- 탐지 결과별 위험도(낮음·보통·높음) 표시
- 탐지 결과 CSV 다운로드, 빈 파일·형식 오류 안내
- 로그인 없는 공개 URL 배포 및 README 작성

### 여유가 있으면 추가
- 탐지 건수 차트, 날짜·위험도 필터, 샘플 여러 종류

### 범위 제외
- 실제 계정 차단, 방화벽 조치, SOAR 자동 집행, 외부 SIEM 연동, 실시간 수집, AI 유료 API, 사용자 로그인/DB

## 4. 입력 형식 및 탐지 기준(교육용)
- **CSV 열:** `timestamp,event_type,user,src_ip,bytes`
- **시간 형식:** ISO 8601 (`2026-11-06T02:01:00+09:00` 등); 시간대가 없는 입력은 KST로 해석한다고 안내
- **event_type:** `LOGIN_FAILURE`, `LOGIN_SUCCESS`, `TRAFFIC`
- **bytes:** `TRAFFIC` 이벤트에서만 필요하며 0 이상의 정수
- **개인정보:** 예시 계정·사설/문서용 IP만 사용하고 원본 업로드 자료는 저장하지 않음

| 탐지 코드 | 기준(초기 설정) | 근거 출력 |
|---|---|---|
| BRUTE_FORCE | 동일 사용자·IP의 로그인 실패가 5분 동안 5회 이상 | 실패 횟수 및 시간 구간 |
| OFFHOUR_LOGIN | 00:00~05:59 KST의 성공 로그인 | 성공 시각 및 해당 계정 |
| TRAFFIC_SPIKE | 5분 단위 트래픽 바이트 합계가 직전 유효한 3개 구간 평균의 2배 초과(기준 평균 0이면 판정 유보) | 현재 합계, 이전 평균, 비교 배수 |

- **위험도(예시):** BRUTE_FORCE=높음, OFFHOUR_LOGIN=보통, TRAFFIC_SPIKE=보통. 한 사건에 여러 근거가 있으면 가장 높은 등급 사용.
- **주의:** 이 규칙은 교육용 예시이며 탐지된 사건을 실제 공격으로 확정하지 않는다.

## 5. 구현 계획
- **기술 구성:** Python 3 + Flask(백엔드 분석 API), HTML/CSS/JavaScript(프론트 화면), 샘플 CSV, pytest 또는 unittest(검증)
- **원칙:** API 키/DB 없이 동작하게 구성하고 업로드 파일의 크기·형식을 검증한다. CSV의 표시 텍스트는 HTML로 해석되지 않도록 처리한다.
- **구조 예시:** `app.py`, `detectors.py`, `templates/index.html`, `static/`, `samples/sample_logs.csv`, `tests/`, `requirements.txt`, `README.md`

### 단계 1 — 기본 흐름
첫 화면, 샘플 데이터 불러오기, CSV 파싱, 분석 실행 버튼 구성.

### 단계 2 — 탐지 구현
세 규칙을 함수로 분리하고 사건별 근거·위험도 JSON 생성. 정상·오류 입력 테스트 작성.

### 단계 3 — 결과 확인
탐지 목록/건수/위험도/설명 표시, CSV 내보내기. 화면과 출력 내용 일치 확인.

### 단계 4 — 배포 및 점검
GitHub 소스 정리, Render 공개 URL 배포, 비로그인 시크릿 창 확인, README/테스트 기록 작성.

|---|---|---|

| T02 | 동일 계정·IP 5분 내 로그인 실패 5회 | BRUTE_FORCE 1건 이상 탐지 |
